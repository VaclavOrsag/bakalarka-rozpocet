Aplikace, vyvinutá v jazyce Python s využitím knihovny Tkinter a databáze SQLite, se zaměřuje na automatizaci zpracování transakcí importovaných primárně z formátu MS Excel. \annotation[english]{The aim of this bachelor's thesis is the design and implementation of a desktop application for effective budget creation and management, serving as a replacement for manual data processing in Excel. Developed in Python using the Tkinter library and SQLite database, the application focuses on automating the processing of transactions imported primarily from MS Excel format. Key features include automatic item categorization, the creation of a hierarchical accounting framework, and real-time budget tracking using the Year-To-Date method. The solution includes an interactive dashboard with visual budget status indicators and an integrated tutorial that intuitively guides the user through the application setup process.}

\section{Úvod}
V dnešní době je efektivní správa financí klíčová pro stabilitu osobních i firemních rozpočtů. Mnoho uživatelů, včetně odborníků, však stále spoléhá na tabulkové procesory, jako je Microsoft Excel. Ačkoliv jsou tyto nástroje flexibilní, při opakovaném zpracování velkého množství transakcí a tvorbě komplexních rozpočtů narážejí na své limity – proces je často zdlouhavý, manuální a náchylný k chybám.

Impulsem pro vznik této práce byla reálná potřeba zefektivnit proces tvorby rozpočtu, který doposud probíhal právě touto manuální cestou. Vedoucí této práce, Mgr. Jiří Zacpal, Ph.D., využíval pro tvorbu rozpočtu systém založený na exportu transakcí z účetního programu a jejich následném zpracování v Excelu. Tento proces zahrnoval ruční analýzu nákladových středisek, manuální tvorbu účetní osnovy a pracné párování jednotlivých transakcí s rozpočtem.

Hlavním cílem této bakalářské práce je vytvořit desktopovou aplikaci „na míru“, která tento proces plně automatizuje a co nejvíce zjednoduší. Aplikace je navržena tak, aby převzala surová data, automaticky je roztřídila do kategorií a umožnila sestavit hierarchii rozpočtu bez nutnosti složitých manuálních zásahů. Důraz je kladen nejen na automatizaci, ale také na uživatelský komfort a vizualizaci. Namísto nepřehledných tabulek aplikace nabídne dashboard s jasnými vizuálními indikátory, které uživateli umožní pohodlně sledovat plnění rozpočtu v reálném čase a okamžitě identifikovat problémové oblasti.

\section{Průzkum existujících řešení}

\subsection{Microsoft Excel}
Microsoft Excel (a obecně tabulkové procesory) představuje jeden z nejrozšířenějších nástrojů pro správu osobních i firemních financí. Jeho hlavní výhodou je obrovská flexibilita – uživatel není vázán logikou aplikace a může si vytvořit strukturu přesně podle svých potřeb.

Právě řešení postavené na Microsoft Excel sloužilo jako přímá inspirace pro tuto bakalářskou práci. Původní systém využíval list ("Zdroj") pro import dat, kontingenční tabulky pro analýzu a 
následně manuální tvorbu rozpočtů (viz Obrázek \ref{fig:excel_showcase}). Ačkoliv je toto řešení funkční, naráží na několik limitů, které má nová aplikace řešit:
\begin{itemize}
    \item \textbf{Absence automatizace:} Toto je nejzásadnější nedostatek původního řešení. V Excelu musel uživatel ručně nastavovat kategorie, hlídat konzistenci dat a manuálně aktualizovat výpočty. Aplikace tento proces plně automatizuje – data se sama zařazují do kategorií, určují se jejich typy a automaticky se přeskupují podle aktuální konfigurace účetní osnovy.
    \item \textbf{Absence plnění:} Excelový systém neobsahoval žádný mechanismus pro sledování plnění rozpočtu. Uživatel musel sám porovnávat skutečné výdaje s plánem, což bylo časově náročné a náchylné k chybám.
    \item \textbf{Křehkost dat:} Při nesprávném zásahu do buňky se vzorcem může dojít k rozbití celého výpočtu.
    \item \textbf{Náročná údržba:} Přidávání nových kategorií nebo změna struktury vyžaduje manuální úpravu mnoha listů a vzorců.
    \item \textbf{Absence validace:} Excel (ve výchozím stavu) nekontroluje, zda uživatel zadal všechna povinná data, což vede k chybám v analýze.
\end{itemize}

\section{Specifikace řešení}
Na základě průzkumu existujících řešení a stanovených cílů byly definovány následující funkční požadavky na aplikaci.

\subsection{Správa profilů a dat}
Aplikace musí podporovat práci s více uživatelskými profily, pro lepší oddělení rozpočtových let.
\begin{itemize}
    \item \textbf{Izolace dat:} Každý profil musí mít svou vlastní oddělenou databázi (SQLite), aby nedocházelo k míchání dat.
    \item \textbf{Správa:} Uživatel musí mít možnost vytvářet nové profily a načítat existující při spuštění aplikace.
\end{itemize}

\subsection{Import a export dat}
Klíčovou funkcí je schopnost zpracovat externí data z Excel souboru.
\begin{itemize}
    \item \textbf{Import z Excelu:} Aplikace bude podporovat import transakcí ve formátu .xlsx. Importní modul musí být schopen načíst specifické sloupce (Datum, Doklad, Zdroj, Firma, Text, MD, D, částka, Cin, číslo, Co, Kdo, Středisko) a správně je mapovat na interní strukturu dat.
    \item \textbf{Rozlišení dat:} Systém musí rozlišovat mezi \textit{historickými} a \textit{aktuálními daty}. To bude sloužit k analýze trendů a sledování plnění rozpočtu v reálném čase.
    \item \textbf{Export dat:} Aplikace umožní exportovat rozpočtový plán do formátu CSV pro další zpracování nebo zálohování.
\end{itemize}

\subsection{Účetní osnova a kategorizace}
Aplikace musí poskytovat flexibilní systém pro kategorizaci transakcí, který kombinuje automatizaci s uživatelským přizpůsobením.
\begin{itemize}
    \item \textbf{Hierarchická struktura:} Uživatel musí mít možnost vytvářet stromovou strukturu kategorií (hlavní kategorie a podkategorie).
    \item \textbf{Typy kategorií:} Systém bude rozlišovat mezi \textit{transakčními kategoriemi} (automaticky vznikají z importovaných dat na základě klíče "Co") a \textit{custom kategoriemi} (uživatelsky definované skupiny pro lepší organizaci).
    \item \textbf{Automatizace:} Aplikace bude automaticky přiřazovat transakce do kategorií a určovat jejich typ (Příjem/Výdej) na základě znaménka částky a metadat z importu.
\end{itemize}

\subsection{Rozpočtování}
Jádrem aplikace je možnost nastavit finanční limity pro jednotlivé kategorie.
\begin{itemize}
    \item \textbf{Plánování:} Uživatel může nastavit rozpočet pro každou kategorii v účetní osnově.
    \item \textbf{Sledování historie:} Při tvorbě rozpočtu aplikace zobrazí historické výdaje v dané kategorii, aby uživateli pomohla nastavit realistický limit.
    \item \textbf{Sledování plnění:} Bude možné sledovat aktuální plnění rozpočtu na základě importovaných aktuálních dat.
\end{itemize}

\subsection{Dashboard a vizualizace}
Dashboard slouží jako hlavní přehledový panel pro rychlou kontrolu finančního zdraví.
\begin{itemize}
    \item \textbf{YTD Metrika:} Aplikace bude sledovat plnění rozpočtu metodou Year-To-Date (od začátku roku do současnosti), což eliminuje sezónní výkyvy v jednotlivých měsících.
    \item \textbf{Barevná indikace:} Stav plnění bude vizualizován pomocí "semaforu":
    \begin{itemize}
        \item \textit{Zelená:} Plnění je v limitu.
        \item \textit{Žlutá:} Mírné překročení limitu (do 5 \%).
        \item \textit{Červená:} Výrazné překročení limitu.
    \end{itemize}
    \item \textbf{Detail měsíce:} Z dashboardu musí být možný přístup do detailu konkrétního měsíce, kde uživatel uvidí rozpad výdajů dle kategorií a jejich plnění.
\end{itemize}

\subsection{Analytické nástroje}
Pro hlubší pochopení finančních toků aplikace nabídne pokročilou analýzu.
\begin{itemize}
    \item \textbf{Pivot Table:} Implementace dynamické kontingenční tabulky, která umožní seskupovat transakce podle různých dimenzí.
    \item \textbf{Presety:} Možnost načítat předdefinované pohledy na data (které vycházejí z excelových šablon).
    \item \textbf{Filtrování:} Možnost filtrovat data podle typu (Příjem/Výdej) a zdroje dat (Historické/Aktuální).
\end{itemize}

\subsection{Správa transakcí}
Uživatel musí mít plnou kontrolu nad jednotlivými záznamy.
\begin{itemize}
    \item \textbf{CRUD operace:} Možnost přidávat, číst, upravovat a mazat jednotlivé transakce.
    \item \textbf{Validace:} Systém bude vizuálně upozorňovat na neúplné transakce (chybějící kategorie, datum nebo částka).
    \item \textbf{Pokročilé filtrování:} Vyhledávání transakcí podle data, částky a kategorie.
\end{itemize}

\section{Použité technologie}

\subsection{Programovací jazyk a framework}
Pro vývoj aplikace byl zvolen jazyk \textbf{Python} verze 3.14.0. Jeho hlavní výhodou je rozsáhlá standardní knihovna a silná podpora pro práci s daty.
Pro tvorbu grafického uživatelského rozhraní (GUI) je využit framework \textbf{Tkinter}. Jedná se o standardní GUI toolkit pro Python, který je multiplatformní a poskytuje dostatečnou sadu ovládacích prvků (widgetů) pro desktopovou aplikaci tohoto typu, včetně pokročilých prvků jako \texttt{Treeview} pro hierarchická data.

\subsection{Databáze a zpracování dat}
\begin{itemize}
    \item \textbf{SQLite:} Pro ukládání dat je využita relační databáze SQLite. Její bezserverová architektura (data uložena v souboru) je ideální pro lokální desktopovou aplikaci, protože nevyžaduje složitou instalaci a konfiguraci na straně uživatele.
    \item \textbf{Pandas:} Pro import a zpracování dat z Excelu je využita knihovna Pandas. Ta umožňuje efektivní načítání souborů .xlsx, čištění dat a jejich transformaci do formátu vhodného pro databázi.
    \item \textbf{CSV:} Standardní modul Pythonu \texttt{csv} je využit pro export dat. Jelikož exportujeme pouze jednoduchý přehled rozpočtu, není potřeba využívat složitější knihovny.
\end{itemize}

\section{Programátorská příručka}
Tato kapitola poskytuje technický pohled na implementaci aplikace. Je určena pro vývojáře, kteří chtějí pochopit vnitřní fungování systému, provádět úpravy nebo rozšiřovat jeho funkcionalitu.

\subsection{Architektura aplikace}
Aplikace je navržena s důrazem na modularitu a oddělení odpovědností (Separation of Concerns). Ačkoliv striktně nedodržuje vzor MVC (Model-View-Controller) v jeho čisté podobě, využívá jeho principy pro organizaci kódu.

\begin{itemize}
    \item \textbf{Model (Data):} Datová vrstva je reprezentována SQLite databází a sadou modulů v adresáři \texttt{app/database/}. Tyto moduly zapouzdřují veškeré SQL dotazy a logiku pro manipulaci s daty.
    \item \textbf{View (Prezentace):} Uživatelské rozhraní je implementováno pomocí knihovny \texttt{tkinter}. Hlavní okno aplikace je inicializováno ve vstupním bodě \texttt{main.py}. Samotná logika zobrazení je pak rozdělena do adresáře \texttt{ui/}, konkrétně do podadresářů \texttt{ui/tabs/} (hlavní funkční celky aplikace) a \texttt{ui/dialogs/} (pomocná a editační okna).
    \item \textbf{Controller (Logika):} Hlavní řídící logiku zajišťuje třída \texttt{App}, která je definována v souboru \texttt{app/controller.py}. Tato třída slouží jako prostředník mezi UI a databází, spravuje stav aplikace a zajišťuje navigaci.
\end{itemize}

\subsection{Adresářová struktura}
Projekt má následující strukturu adresářů a souborů:

\begin{itemize}
    \item \texttt{main.py} – Vstupní bod aplikace. Inicializuje hlavní okno a kontroler.
    \item \texttt{config.py} – Správa konfigurace prostředí a cest k datovým souborům (např. umístění profilů uživatele).
    \item \texttt{app/} – Jádro aplikace.
    \begin{itemize}
        \item \texttt{controller.py} – Hlavní kontroler aplikace.
        \item \texttt{file\_importer.py} – Logika pro import dat z Excelu.
        \item \texttt{file\_exporter.py} – Logika pro export dat do CSV.
        \item \texttt{utils.py} – Pomocné funkce (formátování měny, data).
        \item \texttt{database/} – Moduly pro práci s databází.
        \begin{itemize}
            \item \texttt{manager.py} – Správa připojení k DB a inicializace schématu.
            \item \texttt{budgets\_db.py} – Operace týkající se rozpočtů.
            \item \texttt{dashboard\_db.py} – Výpočty statistik pro dashboard.
            \item \texttt{items\_db.py} – CRUD operace pro transakce.
            \item \texttt{categories\_db.py} – Správa kategorií a jejich hierarchie.
            \item \texttt{categorization\_manager.py} – Logika automatického přiřazování kategorií.
            \item \texttt{analysis\_db.py} – Agregace dat pro kontingenční tabulku (pivot table).
        \end{itemize}
    \end{itemize}
    \item \texttt{ui/} – Uživatelské rozhraní.
    \begin{itemize}
        \item \texttt{tabs/} – Adresář obsahující moduly pro jednotlivé záložky. Každá záložka reprezentuje samostatný funkční celek aplikace (např. Dashboard, Rozpočet).
        \begin{itemize}
            \item \texttt{home\_tab.py} – Úvodní obrazovka záložka \textbf{"Home"}, která provází uživatele tutoriálem. Po jeho dokončení se změní na Dashboard.
            \item \texttt{dashboard\_tab.py} – Implementace logiky \textbf{Dashboardu} (přehled měsíčního plnění), který je součástí Home tabu.
            \item \texttt{sources\_tab.py} – Záložka \textbf{"Transakce"}. Umožňuje správu, filtrování a import historických i aktuálních transakcí.
            \item \texttt{accounting\_structure\_tab.py} – Záložka \textbf{"Účetní osnova"}. Slouží k tvorbě a úpravě účetní osnovy.
            \item \texttt{budget\_tab.py} – Záložka \textbf{"Rozpočet"}. Umožňuje nastavovat finanční limity (rozpočty) pro jednotlivé kategorie.
            \item \texttt{analysis\_tab.py} – Záložka \textbf{"Analýza"}. Poskytuje dynamický pohled na data formou kontingenční tabulky (pivot table).
        \end{itemize}
        \item \texttt{dialogs/} – Adresář s moduly pro modální dialogová okna. Ta slouží k interakci s uživatelem nad rámec hlavního okna.
        \begin{itemize}
            \item \texttt{welcome\_dialog.py} – Správa profilů při spuštění aplikace.
            \item \texttt{item\_dialog.py} – Formulář pro přidání nebo editaci transakce.
            \item \texttt{hierarchy\_dialog.py} – Nastavení zobrazených řádků v analýze.
            \item \texttt{stats\_dialog.py} – Detailní náhled statistik konkrétního měsíce.
        \end{itemize}
    \end{itemize}
\end{itemize}

\subsection{Datový model}
Aplikace využívá relační databázi SQLite. Každý uživatelský profil má svůj vlastní soubor \texttt{.db}, což zajišťuje izolaci dat. Struktura databáze je navržena tak, aby podporovala hierarchickou kategorizaci a rychlé analytické dotazy.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{obrazky/er_diagram.png}
    \caption{Entitně-relační diagram (ERD) databáze}
    \label{fig:erd_detail}
\end{figure}

Databáze se skládá ze tří hlavních tabulek, jejichž vztahy jsou znázorněny na diagramu \ref{fig:erd_detail}:

\begin{itemize}
    \item \textbf{kategorie} – Definuje stromovou strukturu účetní osnovy.
    \begin{itemize}
        \item Sloupec \texttt{parent\_id} realizuje hierarchii (vazba na sebe sama).
        \item Sloupec \texttt{is\_custom} rozlišuje typ kategorie:
        \begin{itemize}
            \item \texttt{0 (Leaf):} Koncová kategorie, která obsahuje transakce a má definovaný rozpočet. Nemůže mít podkategorie.
            \item \texttt{1 (Custom):} Agregační kategorie (složka), která slouží k seskupování jiných kategorií. Nemůže obsahovat transakce přímo, její hodnoty se počítají jako součet podkategorií.
        \end{itemize}
    \end{itemize}
    
    \item \textbf{items} – Obsahuje jednotlivé transakce
    \begin{itemize}
        \item Každá transakce je navázána na jednu kategorii (vazba N:1).
        \item Sloupec \texttt{is\_current} rozlišuje mezi historickými (0) a aktuálními (1) daty.
    \end{itemize}
    
    \item \textbf{rozpocty} – Tabulka pro definici finančních plánů a optimalizaci výkonu.
    \begin{itemize}
        \item Obsahuje plánovaný rozpočet (\texttt{budget\_plan}) pro danou kategorii.
        \item Slouží také jako cache pro \textit{pre-computed metrics} (sloupce \texttt{sum\_past} a \texttt{sum\_current}). Místo opakovaného sčítání tisíců transakcí při každém zobrazení dashboardu jsou tyto hodnoty předpočítány a aktualizovány při každé změně v tabulce \texttt{items}.
    \end{itemize}
\end{itemize}

\textit{Poznámka k diagramu:} Ačkoliv je hierarchie kategorií realizována v rámci jedné tabulky, aplikační logika striktně vynucuje pravidlo, že podkategorie mohou mít pouze kategorie typu Custom. Naopak transakce mohou obsahovat pouze kategorie typu Leaf.

\subsection{Klíčové algoritmy}
\subsubsection{Kategorizace transakcí}
Jedním z nejdůležitějších algoritmů je automatické přiřazování transakcí do kategorií. Algoritmus pracuje na základě sloupce \textbf{Co} z importovaných dat.
\begin{enumerate}
    \item Při importu se zkontroluje, zda hodnota ve sloupci \textbf{Co} odpovídá existující kategorii v tabulce \texttt{kategorie}.
    \item Pokud odpovídající kategorie existuje, transakce je k ní přiřazena. A zároveň se aktualizují všechny relevantní části aplikace (dashboard, rozpočet, analýza).
    \item Pokud kategorie neexistuje, transakce zůstane nezařazená (bez vazby na kategorii). Uživatel ji následně musí v aplikaci ručně klasifikovat (přidat do účetní osnovy).
\end{enumerate}

\subsubsection{Optimalizace výpočtů (Pre-computed Metrics)}
Aby aplikace zůstala responzivní i při velkém množství transakcí, není efektivní provádět kompletní agregaci dat (SQL \texttt{SUM}) při každém překreslení uživatelského rozhraní. Místo toho je využit mechanismus tzv. \textit{pre-computed metrics}, který je implementován v modulu \texttt{dashboard\_db.py}.

Tento systém funguje na principu inkrementálních aktualizací a cachování výsledků v tabulce \texttt{rozpocty}. Proces probíhá v následujících krocích:

\begin{enumerate}
    \item \textbf{Trigger události:} Jakákoliv změna v datech (import, přidání, editace nebo smazání transakce) vyvolá funkci pro přepočet statistik.
    \item \textbf{Agregace na úrovni Leaf:} Nejprve se spočítají součty pro koncové (\textit{Leaf}) kategorie. SQL dotaz sečte částky transakcí seskupené podle \texttt{kategorie\_id} a typu dat (historická vs. aktuální).
    \item \textbf{Uložení do mezipaměti:} Výsledné hodnoty se ukládají do tabulky \texttt{rozpocty}, konkrétně do sloupců \texttt{sum\_past} a \texttt{sum\_current}. Tím je zajištěno, že pro zobrazení Dashboardu nebo Rozpočtu stačí číst pouze tuto malou tabulku, nikoliv prohledávat celou historii transakcí.
    \item \textbf{Roll-up pro Custom kategorie:} V posledním kroku se provede rekurzivní součet směrem nahoru. Hodnoty pro rodičovské (\textit{Custom}) kategorie jsou vypočítány jako součet hodnot jejich přímých potomků. Tento výpočet probíhá v paměti aplikace (Python) nad již agregovanými daty, což je řádově rychlejší než rekurzivní SQL dotazy.
\end{enumerate}

Tento mechanismus okamžité aktualizace je ideální pro běžnou práci (přidání jedné transakce), ale při hromadném importu tisíců položek by byl neefektivní. Proto je v modulu \texttt{file\_importer.py} implementována optimalizace: při importu se volá funkce \texttt{add\_item} s parametrem \texttt{skip\_metrics\_update=True}. Tím se dočasně potlačí přepočet statistik. Teprve po úspěšném vložení všech záznamů se zavolá funkce \texttt{update\_all\_metrics} (z modulu \texttt{items\_db.py}), která provede hromadný přepočet celé databáze najednou. Tím se doba importu zkracuje z desítek sekund na zlomky sekundy.

Díky tomuto přístupu je zobrazení Dashboardu prakticky okamžité, bez ohledu na to, zda databáze obsahuje stovky nebo desetitisíce transakcí.

    \item \textbf{žlutá barva} – YTD plnění rozpočtu překračuje limit, ale je v rozmezí 5\%
    \item \textbf{červená barva} – YTD plnění rozpočtu překračuje více než 5\%
\end{itemize}

\textbf{Leden} máme plnění 14.4\% což je výrazně nad limitem 8.33\% a tlačítko je červené, proto můžeme kliknout na tlačítko \textbf{Leden} a podívat se na detailní analýzu tohoto měsíce 
(viz Obrázek \ref{fig:month_analysis}). 

\subsubsection{Měsíční analýza}
Po kliknutí na tlačítko měsíce se nám zobrazí podrobnější analýza daného měsíce (viz Obrázek \ref{fig:month_analysis}).
\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{month_analysis.png}
    \caption{Měsíční analýza}
    \label{fig:month_analysis}
\end{figure}
Na obrázku \ref{fig:month_analysis} vidíme opět naši hierarchii kategorií z účetní osnovy, ale tentokrát s podrobnějšími informacemi o daném měsíci.
Zobrazení hierarchie je stejné jako v záložce \textbf{Rozpočet}, ale máme zde nové sloupce:
\begin{itemize}
    \item \textbf{Min. transakce} – součet všech minulých transakcí v dané kategorii za vybraný měsíc.
    \item \textbf{Akt. transakce} – součet všech aktuálních transakcí v dané kategorii za vybraný měsíc.
    \item \textbf{\%(M->M)} – procentuální změna mezi minulými a aktuálními transakcemi za vybraný měsíc.
    \item \textbf{Rozpočet} – plánovaný rozpočet pro danou kategorii.
    \item \textbf{Plnění R.} – aktuální plnění rozpočtu pro danou kategorii YTD (Year-To-Date, od začátku roku).
    \item \textbf{\%(R)} – procentuální plnění rozpočtu pro danou kategorii YTD.
\end{itemize}
Zároveň dole vlevo vidíme hodnotu \textbf{Celkem}, tato hodnota zobrazuje plnění celkového rozpočtu YTD. Tuto hodnotu v \% můžeme vidět i na tlačítku měsíce v dashboardu (viz Obrázek \ref{fig:complete_dashboard}). 
V dashboardu se nám díky hodnotě \textbf{14.4\%} zobrazuje tlačítko červeně. Zde, ale vidíme, celkové plnění rozpočtu YTD a můžeme tak vyvodit, že i přes to, že jsme tento měsíc utratili více než je náš fixní limit, 
tak celkově jsme stále pod limitem v rámci rozpočtu a detailně vidíme přesnou částku. 

Je normální, že v některých měsících utratíme více a v jiných méně. Sledování celkového plnění rozpočtu v rámci roku nám umožňuje identifikovat, které měsíce jsou více příjmové/výdajové a které méně. 
Detailnější analýza měsíce nám umožňuje lépe porozumět našim finančním návykům a plánovat budoucí rozpočty efektivněji.

\begin{kiconclusions}
Cílem této bakalářské práce bylo navrhnout a implementovat desktopovou aplikaci pro tvorbu a správu rozpočtu, která by nahradila stávající manuální proces založený na tabulkovém procesoru Microsoft Excel. 

V rámci práce byla provedena analýza existujících řešení, která potvrdila, že ačkoliv jsou nástroje jako Excel vysoce flexibilní, postrádají potřebnou automatizaci a validaci dat. Na základě těchto zjištění byla navržena aplikace v jazyce Python s využitím knihovny Tkinter pro grafické rozhraní a databáze SQLite pro ukládání dat.

Výsledná aplikace úspěšně naplňuje stanovené cíle. Umožňuje importovat transakce z excelu nebo manuálně, automaticky je kategorizovat a na základě toho tvořit účetní osnovu, která zjednoduší sestavení rozpočtu. 

Největší výzvou při návrhu bylo nalezení rovnováhy mezi automatizací a flexibilitou. Podařilo se vytvořit systém, který většinu rutinních úkonů provádí automaticky (např. detekce typu transakce, párování kategorií), ale zároveň umožňuje uživateli kdykoliv zasáhnout, upravit strukturu osnovy nebo manuálně přeřadit položky.

Zvolená technologie Tkinter se ukázala jako vhodná pro rychlý vývoj desktopové aplikace, nicméně při implementaci složitějších vizualizací a moderních UI prvků narážela na své limity. Pro budoucí rozvoj aplikace by bylo vhodné zvážit přechod na modernější framework nebo webové rozhraní, které by umožnilo snadnější přístup z více zařízení a modernější design uživatelského rozhraní.

Do budoucna se nabízí také rozšíření analytických funkcí. Aplikaci by bylo vhodné obohatit grafy pro lepší vizualizaci dat a implementovat detailnější možnosti filtrování pro hlubší analýzu transakcí. Významným krokem vpřed by byla také podpora vytváření vlastních profilů s možností definovat odlišnou strukturu databáze, což by výrazně zvýšilo univerzalitu nástroje. 

Vytvořená aplikace však již v současné podobě představuje funkční a efektivní nástroj, který výrazně zrychluje a zpřehledňuje proces rozpočtování.
\end{kiconclusions}
